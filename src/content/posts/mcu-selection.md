选型最怕的不是选错参数，是**选了一个后面买不到的芯片**。2021 年那波缺货，多少人被迫把画好的板子重画一遍。

这篇给一套**排除法**：先按硬需求砍掉一大批，再在剩下的里挑。

## 第一步：先砍掉不可能的

### 要不要联网？

这是最大的分水岭。

| 需求 | 直接排除 |
|---|---|
| 要 WiFi / BLE | 所有纯 MCU（STM32F1、GD32、RP2040…）——除非外加模块 |
| 只做本地控制 | ESP32 系列（贵、功耗高、启动慢、实时性一般） |

**「主控 + 外挂 WiFi 模块」vs「ESP32 单芯片」** 是常见纠结：

- 外挂方案：主控专注实时控制，WiFi 挂了不影响主逻辑；代价是 BOM 多一颗、串口协议要自己定
- ESP32 单芯片：省成本省面积；代价是 WiFi 协议栈抢占 CPU、深睡唤醒慢、模拟性能一般

> 经验：**电机控制、精密采样**别用 ESP32 当主控；**数据上报、远程控制**用 ESP32 最省事。

### 要几路什么外设？

先列硬指标，逐条对：

```text
UART × 3    SPI × 2    I2C × 2    CAN × 1
ADC 12bit × 6 通道，≥ 100ksps
PWM × 4 路，≥ 20kHz
IO 总数 ≥ 28
```

这一步能砍掉一大半。比如要 CAN，STM32F103C8T6 只有 1 路 CAN 但**没有 USB 和 CAN 同时用**的引脚冲突问题；而 STM32G0 部分型号干脆没 CAN。

**常见坑：外设「有」不等于「够用」**

- ADC 有 10 个通道，但**不能同时采样**（只有一个采样保持器）→ 要同步采样就得选带多 ADC 的型号
- 定时器有 4 个，但高级定时器（带死区、刹车）可能只有 1 个 → 三相电机要 1 个高级 + 互补输出
- SPI 有 2 路，但**共用 DMA 通道** → 高速传输会打架

这些只能翻数据手册的「Alternate function mapping」和「DMA request mapping」表，别只看首页参数。

## 第二步：四类主控的定位

### STM32：生态最厚，价格最高

**适合**：工业控制、需要长期供货保证、团队已有积累。

- 文档、CubeMX、HAL/LL、社区问答都是最全的
- 型号覆盖面极广：从 F0（几分钱级）到 H7（480MHz）
- 缺点：贵，且缺货时涨得最凶

**子系列怎么选**：

| 系列 | 内核 | 定位 |
|---|---|---|
| F0 / G0 | M0+ | 低成本、低功耗，替代 8 位机 |
| F1 / F3 | M3 / M4F | 经典通用，F1 已属「legacy」但资料最多 |
| F4 / G4 | M4F | 带 FPU 和 DSP 指令，G4 还带数学加速器，适合电机/电源 |
| L4 / L5 | M4F | 低功耗，L5 带 TrustZone |
| H7 | M7 | 高性能，外挂 SDRAM |

### GD32 / AT32 / 国民技术：Pin2Pin 替代

**适合**：成本敏感、STM32 缺货时的备选。

- GD32F103 与 STM32F103 **引脚兼容**，多数情况改个时钟配置就能跑（GD32 主频更高，108MHz vs 72MHz）
- 但**外设行为有细微差异**：ADC 采样时间、Flash 等待周期、某些寄存器的复位值
- 移植时务必跑一遍完整回归，尤其是时序敏感的部分（I2C 从机、USB、CAN 波特率）

> 现实建议：**要么一开始就用国产，要么在原理图上留好兼容位**（比如 R/C 的参数按两家都能满足来选）。中途切换的代价比想象中大。

### ESP32 系列：联网场景的默认答案

**适合**：IoT 终端、需要 WiFi/BLE、对实时性要求不极端。

| 型号 | 内核 | 特点 |
|---|---|---|
| ESP32（经典） | 双核 LX6 240MHz | 外设最全，双核，功耗较高 |
| ESP32-S3 | 双核 LX7 + 向量指令 | 带 USB OTG、AI 加速指令，适合带屏/摄像头 |
| ESP32-C3 | 单核 RISC-V 160MHz | 便宜、够用，WiFi+BLE5 |
| ESP32-C6 | RISC-V + WiFi6/Thread | 新协议栈 |

⚠️ **ESP32 不适合当「纯实时控制器」**：WiFi 协议栈会周期性关中断，抖动可达几百微秒。
真要两者兼顾，用**双核**：一个核跑 WiFi，另一个核跑控制（`xTaskCreatePinnedToCore`）。

### RP2040：便宜大碗，PIO 是王牌

**适合**：教学、小批量、需要「自定义外设」的场景。

- 双核 M0+ 133MHz，264KB RAM（比同价位 STM32 多一个数量级）
- **PIO**（可编程 IO）是独门武器：可以用汇编实现任意时序协议（WS2812、DVI、自定义并口）
- 缺点：**没有内部 Flash**（要外挂 QSPI Flash）、**没有 EEPROM**、ADC 只有 12bit 4 通道、**没有 CAN**
- 深度休眠功耗不如 STM32L 系列

## 第三步：容易被忽略的五个维度

### 1. 封装与焊接

QFN / BGA 便宜但手工焊不了。**打样阶段优先 LQFP**，量产再换 QFN 降成本。

### 2. 温度等级

商业级 0~70℃、工业级 -40~85℃、扩展 -40~125℃。

户外设备、汽车电子**必须工业级**。注意：同一型号不同后缀温度等级不同，采购时看后缀。

### 3. Flash / RAM 够不够（留 30% 余量）

```text
Flash：当前固件 + 未来 3 个版本的功能 + bootloader + 文件系统
RAM：  当前 .data+.bss + 最大栈深度 × 2 + 堆（如果用）
```

STM32F103C8T6 只有 20KB RAM，跑个 FreeRTOS + 几个任务 + 串口环形缓冲就见底了。**这块最容易估少。**

### 4. 调试接口

SWD 两线就够（SWDIO + SWCLK）。但**一定要引出来**，而且别被外壳挡住。

有些国产芯片只支持 JTAG 或专用调试器，买之前确认手上有工具。

### 5. 供货与生命周期

- 查原厂官网的 **Product Longevity / PCN 公告**
- 优先选**已经量产 3 年以上、且仍在推荐列表**的型号
- 关键项目**准备第二供应商**（Pin2Pin 或至少功能对等）

## 一张决策表

| 场景 | 首选 | 备选 |
|---|---|---|
| 通用控制 + 长期供货 | STM32G0 / G4 | GD32、AT32 |
| 电机 / 数字电源 | STM32G4（数学加速器 + 高级定时器） | TI C2000 |
| WiFi 上报 / 智能家居 | ESP32-C3 / S3 | ESP32 经典 |
| 超低成本、简单逻辑 | CH32V003（RISC-V，极便宜） | STM32F0、8 位机 |
| 教学 / 创意项目 / 要多 RAM | RP2040 | STM32F4 |
| 低功耗电池设备 | STM32L4 / L5 | EFM32、nRF52 |
| 高精度模拟 | STM32F3（内置运放比较器） | 外挂专用 ADC |

## 我自己的选型流程

```text
1. 写需求表（外设数量、IO 数、温度、供电、成本上限）
2. 用「要不要联网」先砍一半
3. 在 2~3 个候选里，各画一个最小系统（引脚分配表）
4. 查供货：立创/贸泽/得捷的库存 + 原厂生命周期
5. 买 3 片打样，跑通「点灯 + 串口 + 最难的那个外设」
6. 通过再画正式板
```

**第 3 步最容易发现隐藏冲突**——引脚分配画完才发现 ADC 通道和 SPI 抢引脚，或者调试口被占用。

**第 5 步别省**。用最小系统板跑通最难的外设（比如 USB、CAN、高速 ADC），比在正式板上 debug 便宜十倍。

## 小结

选型的本质是**排除**，不是打勾：

1. **联网与否**是最大的分界线
2. **外设数量要翻手册确认**，不是看首页
3. **国产替代要么早用，要么留兼容位**
4. **RAM 留 30%，Flash 留 30%**
5. **供货查三次**：现在有货、半年后有货、三年后还在产

最后一句：**别为了「以后可能要用」选大芯片**。选大了成本高、功耗高、焊接难；选小了换型号重画板。按当前需求 + 30% 余量就是最优解。
